## 2026-10-09 决策引导修正

- 空闲求助区保持紧凑，并按运行中、已结束、额度不足、自动 Advisor、停止或超时说明 Hint 为什么不可用及下一步；有待处理请求时仍显示证据、输入与明确操作按钮。
- 输入区显示只读格式预览，复用既有解析规则。识别参数、未匹配规则、连接或接口不可用独立表述；原始草稿不会被预览改写，识别参数不表示动作变化或采纳。
- 结束原因直接显示在顶部；已结束的超时请求不再暗示正在回退。Advisor 诊断失败与原生任务结果独立。
- 无失败摘要不会被当成错误；尝试详情依据实际尝试状态标记，原生任务未达标与执行错误分别显示。后端策略、解析规则、请求生命周期与历史记录语义保持。

## 历史四区域设计

1. **顶部状态条**：常驻且随页面滚动保留。当前任务、唯一的阶段与尝试计数、执行目标、真人/自动求助方式、可用与预留求助额度、run 切换、新建 run 和紧急中断都在这里。橙色大块“需要你操作”最醒目；无需操作为绿色，断连时为红色“无法确认”。断连/旧快照、预览画面未更新、回复超时、资源不足和中断收据保持可见。`requested`、`stop_unconfirmed`、`too_late` 均不能显示为已确认停止，只有 `stopped` 收据可确认。
2. **执行画面与历史**：独立保留当前画面和每次尝试的回放、完整动作时间轴、展开参数、点击定位、同步采样/旧录像近似定位、缺录像及超出范围提示、原生结果校验、源分辨率与原图。长执行标识与完整录制信息放“执行与录制详情”；录像截断仍在标题旁提示。普通刷新复用视频节点、实时图像与下载循环，播放位置、历史选择、动作展开和定位高亮保留。
3. **当前求助与回复**：合并原 inbox 与 request detail。求助原因、需要判断的问题、最多三条相关事件摘要、对应回放入口、倒计时、草稿输入与提交/稍后/取消在一个区域；审批使用批准/拒绝。打开对应历史时间轴后，求助区只链接该时间轴，避免重复列出同一 trace。历史请求折叠，查看历史不会把当前待处理请求的输入区替换掉。无可操作请求时收紧为“当前无需操作”。
4. **回复反馈与最终结果**：收到提交确认后，提交、后续执行关联、实际控制差异、关联尝试的原生结果作为四张独立卡片显示。缺少关联或控制证据时明确写无法确认；即使 SDK 参数不同且原生成功，也不推断因果采纳。自动回退单独标识。终态显示已校验任务成功/未成功或结果待校验，以及简短停止原因；完整 Eval 诊断和原文按需展开。诊断完成仍不能表示任务成功。

## 按阶段展示

| 阶段 | 顶部操作指引 | 当前求助与回复 | 回复反馈与最终结果 |
| --- | --- | --- | --- |
| 尚无 run / 新 run 注册中 | 当前无需操作；新建入口或注册状态 | 紧凑的当前无需操作 | 等待回复和结果 |
| 准备 / 执行 | 当前无需操作；当前尝试与阶段 | 紧凑的当前无需操作 | 有先前回复则保留四层反馈，否则简短等待提示 |
| 等待真人 hint | 橙色需要你操作；倒计时与跳转入口 | 当前证据、格式引导、输入与操作 | 只显示实际已有反馈 |
| 等待真人审批 | 橙色需要你操作 | 证据与批准/拒绝；没有 hint 输入框 | 同上 |
| 提交成功 | 下一阶段由服务端快照决定 | 请求离开 pending 后收紧；历史折叠 | 显示提交确认，后面三层仍可能无法确认 |
| 提交失败/结果不明 | 保留当前状态与草稿 | 输入及选择不丢，错误不误标成功 | 明确提交未成功确认；无采纳结论 |
| 回复超时 / 自动回退 | 醒目提示超时；当前无需操作 | 过期请求不再提供提交按钮，保留历史证据 | 运行端进入 fallback 或存在 proxy 回复时标识自动回退 |
| 已请求停止 | 显示已请求、执行器尚未确认；不再邀请答复 | 当前无需操作 | 已有回复证据保持，不能宣称停止成功 |
| 未确认停止 / 停止到达过晚 | 显示未确认或未生效 | 当前无需操作 | 不能用 cancelled/completed 代替确认收据 |
| 已确认停止 / 本轮结束 | 明确停止收据与终态 | 当前无需操作，历史折叠 | 原生任务结果、停止原因、完整 Eval 展开入口 |
| Store 断连 | 红色无法确认是否需要操作，旧快照/过期画面警告 | 原草稿、选区与焦点保持 | 旧证据仍可读；重连后只清旧读取错误 |

倒计时在无业务快照变化时也更新；它使用浏览器时钟控制展示，正式超时、回退与停止状态仍由运行端持久记录决定。取消、延后、批准、拒绝、hint 提交和紧急中断的 API 与 payload 均沿用原实现。

## 提示格式引导

输入区旁提供可点击的草稿预设和参数范围。预设不会自动提交，不会改写任意已有回复；实际传递和编译记录仍来自后端。

- `robosuite / cube_lift`：中文预设“降低抓取高度，夹紧后确认抓牢”；参数示例为 `AB_CONTROL_V1 grasp_offset_m=0.005;approach_tolerance_m=0.004;close_settle_steps=30;`。
- RoboCasa：参数示例为 `AB_CONTROL_V1 grasp_offset_m=0.045;open_settle_steps=20;close_settle_steps=30;`，并列出本 suite 的有界参数范围；不显示 cube_lift 中文预设。
- 其他目标：明确没有已验证的参数/中文预设证据。

范围核对来源为现有 `hint_compilation.py` 与 `protocol/v2/guidance_adoption_v1/control_compiler.py`。界面说明普通中文不一定改变动作，格式可识别也不代表当前策略使用或动作采纳；不增加一套可能与后端漂移的客户端解析器。
