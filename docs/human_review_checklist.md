# 真人复核清单（四轮 computer use 之后）

> 前四轮已用 computer use 修好 12 个 UI bug、确认采纳链路（限定范围）通了。剩下的这些是**只能真人判**的：物理因果、主观可用性、物理零动作。按顺序做，每项留证据。

## A. 物理因果（机器人真的因为你的回复动了没）——核心

这是四轮里唯一没被证实、也最该你亲眼看的事。

1. 从 UI 建一个会求助的 run（`reactive_help` 或 `full_trace_aware_attention_planner`）。
2. 等求助请求出现，输入一条**明确指令**（比如"抓取时往下 1.5 厘米、容差收紧"）。
3. **盯着机器人的物理动作**（相机/画面），看它是否真的按你说的变了——不只是参数栏显示变了。
4. **对照**：同一个 seed 再跑一遍"不给指令"，看动作差异。

**判定**：物理动作真的随回复变了 = 因果成立；只有参数/标签变了、物理动作看不出差异 = 仍存疑，记"证据不足"。

## B. 主观可用性（看得懂、用得顺）——只能你判

- [ ] 求助请求的展示（类型/原因/优先级/deadline）**看得懂**吗？
- [ ] 错误提示足够明确吗？你能知道下一步做什么吗？
- [ ] 输入 hint → 提交 → 稍后处理 → 取消，这套操作**顺不顺**、会不会误触？
- [ ] 四层采纳证据（提交→关联→动作变化→成功）在 UI 里**容易找**吗，还是藏在深处？
- [ ] 画面/回放**够不够**你判断"机器人到底做了什么"？

这些 computer use 只能点、不能"觉得"，所以只有你能判。

## C. 物理零动作（等待/停止后真的不动）

- [ ] 等待真人回复期间，**盯着机器人**——它真的不动吗？（不是看 `robot_actions` 字段，是看物理动作）
- [ ] 点中断/停止后，机器人**真的停了**吗？有没有"确认停止后还在动"？

## D. 未覆盖项（能补就补，不能就记）

- [ ] **自然审批**：如果有带审批门的配置，测"批准/拒绝"按钮；没有就记"仍无触发条件"。
- [ ] **真实断网**：手动断网（或隔离机），看 UI 是否把旧画面标过期；和"停 UI 服务"是两码事，分开记。
- [ ] **授权回放**：看有没有相机回放；回放时刷新会不会被打断。

## E. 记录格式（和 computer use 同款）

```
时间(北京时间) / run ID → 你做了什么 → 期望 → 实际 → 截图 → 判定:通过/失败/证据不足/未覆盖
```

- 关键阶段连续录像；不把"看不出来"写成通过；不用一次成功背书整个 workflow。

## 判定口径

- **通过**：实际与预期一致，有原始证据。
- **失败**：与预期不符。
- **证据不足**：UI/画面提供不了足够信息，明说缺什么。
- **未覆盖**：无合法触发条件，注明原因。
