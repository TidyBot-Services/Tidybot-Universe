# AttentionBench 四区域重构验收包

范围固定为当前 `feature/attention-native-robosuite` 工作树的展示层；继承所有现有未提交修复。后端语义、策略、锁定配置、原生结果、服务进程、真实 run 与请求均不改变。

交付：`index.html`、`live.js`、扩展的真实 Chromium DOM 测试、信息架构与逐项迁移对照、红绿日志。只有 projection 必须变动时才改后端并加单测。

通过标准：

1. 主界面恰有顶部状态、执行画面与历史、当前求助与回复、回复反馈与最终结果四区。阶段覆盖准备、执行、等待真人、提交后、超时回退、停止请求、确认停止、终态；空求助收紧。
2. 顶部突出操作需求，唯一展示本轮运行阶段与尝试计数。保留 run 切换、新建、紧急中断、断连与过期、回复超时、停止未确认；资源不足有摘要。
3. 回放、完整动作时间轴、参数、点击同步/近似定位、当前/历史区分、分辨率、录制范围、最新执行绑定不丢失；普通刷新保留视频节点和帧传输。
4. 当前请求紧邻证据和操作；历史折叠；中文/参数格式范围如实引导。草稿、选区、焦点、重启授权续期、单次提交保持。
5. 提交、后续执行关联、控制差异、原生结果四层独立；无法确认和自动回退明确显示；模型诊断不代替原生成功。
6. 设置/资源/实验统计/开发调试/原始记录均有二级入口，同 run 刷新保留打开状态，换 run 不串状态。完整 Eval 按需展开。
7. 新增 DOM 目标测试在原代码运行失败后实现；完整 DOM 与 Harness 回归通过，Python 不低于现有 539 passed / 10 skipped；语法与 diff 检查通过。

证据位置：`outputs/ui-four-regions/`。基线副本保留在 `before/`，每轮日志保留。测试 API 为隔离 fixture，媒体为真实编码视频；这次是 UI 工程验收，不开展机器人正式实验或真人决策效果验收。
