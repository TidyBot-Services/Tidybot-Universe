1. **先红后绿（强制）**：每个修复先写一个能在**原代码上复现失败**的测试（保留"红"日志），修复后该测试通过（保留"绿"日志），两份日志都要留。**前端问题必须用真实 DOM/交互测试**（点击/输入/刷新/断连），仅 `grep` 源码字符串不算验证。
2. **允许隔离测试**：本轮可用临时 store、mock、测试 HTTP 服务、定向重启/断连测试。**第一轮的 store 与证据目录保持只读**，不得写入。
3. **可观测性必须来自真实证据**：
   - `store.py:264` 的 `robot_actions: 0` 是**固定字段**，仅展示它不能证明整个等待窗口零动作。须记录**等待起止时间 + 执行器动作计数的覆盖范围**，用真实动作计数证明。

4. **未覆盖项先查触发条件，不造入口**：
   - 前端**已有**批准/拒绝按钮（`ui/live.js` 批准/拒绝分支），第一轮缺的是**自然审批请求**。应查合法触发路径（哪个策略/哪类请求会产生 approval），**不得新增"造审批请求"按钮冒充覆盖**。
