# AttentionBench collaborator workspace

## Prerequisites

Use Linux x86_64 with an NVIDIA GPU and a working driver, Git, Python 3, `uv`, Conda, `bwrap`, enabled unprivileged user namespaces, and a Codex account with access to `gpt-6.1-sol`. Reserve roughly 50 GB for installed software and assets and **at least 60 GB free** before bootstrap. `doctor` enforces the latter. Sign in with `codex login`; install the CLI version pinned by `attentionbench.lock.json`.

In Docker, run the container with `--gpus all --security-opt seccomp=unconfined --security-opt apparmor=unconfined --security-opt systempaths=unconfined`: the agent's `bwrap` sandbox needs user namespaces and its own `/proc` (verified 10-31; `--privileged` is not needed).

## Four commands

Clone this repository **into the workspace** (a real directory, not a symlink), then run from it:

```bash
git clone -b attentionbench/baseline-20261015 https://github.com/TidyBot-Services/Tidybot-Universe.git /absolute/attentionbench-workspace/repos/attentionbench
cd /absolute/attentionbench-workspace/repos/attentionbench
scripts/attentionbench/bootstrap.sh --workspace /absolute/attentionbench-workspace
scripts/attentionbench/doctor.sh --workspace /absolute/attentionbench-workspace
scripts/attentionbench/start.sh --workspace /absolute/attentionbench-workspace
scripts/attentionbench/stop.sh --workspace /absolute/attentionbench-workspace
```

Use `bootstrap.sh --dry-run --workspace DIR` to print the plan without creating `DIR`. To use a complete existing official RoboCasa asset tree, add `--assets-from /absolute/path/to/robocasa/models/assets`; it is read and SHA256 checked. `--skip-planner` prepares the rest of the workspace. The planner chain assembles its parent project from this checkout, its tracked OpenArm model, the pinned official cuRobo checkout, and `repos/robocasa_tasks` at `b18bbf1585c42e370ae45ababdddad700cc2c71d`. The native asset tree defaults to `DIR/data/robocasa365/assets`. `--planner-project-from` remains an override for an existing complete project tree; `--planner-native-assets-from` overrides the native asset source. Missing or differing inputs stop the chain with the affected step and entries.

Bootstrap creates `repos/`, `envs/`, `sim/`, `deployments/`, and `data/`; checks out exact commits; makes a Python 3.10 UI environment, a Python 3.11 simulator environment, and `envs/curobo-env` from the committed Conda and pip specifications; downloads and verifies the official locked assets; writes relative `paths.json` values; initializes the UI and Memory stores; and creates private random Memory keys. The planner step checks the official source and 70,254 native files, writes an r12-schema official lock, derives d05 and d06, runs two fixed isolated local plans, writes a protected 0444 local trust registry, and materializes a dev-local snapshot. Planner stamps are under `data/installer/stamps/`. The native tree is about 8.2 GB, the author's cuRobo environment about 15 GB, and the r12 project about 70 MB. Allow at least 60 GB free; asset transfer, hashing and Conda installation can each take tens of minutes or longer. A changed planner stamp requires repair of its inputs or removal of that step's outputs and stamp before retrying.

`start.sh` launches Memory on loopback port 8878 and the UI on loopback port 8769, waits for both health checks, and prints the UI address. PID files and logs are under `data/run/`. Use `--ui-port` and `--memory-port` to choose other ports. `stop.sh` terminates only processes recorded in that workspace.

## Troubleshooting

Each bootstrap error names its step, command failure or mismatch, and a repair. If asset verification fails, the listed files must be replaced from the official source; bootstrap never changes mismatching files. If `doctor` reports no GPU, check the NVIDIA driver and `torch.cuda.is_available()` in `envs/curobo/bin/python`. For isolation failures, install bubblewrap and enable unprivileged user namespaces. For login or version failures, run `codex login` or install the lock's CLI version. For a busy port, stop the owning process or choose another port at start. For a missing `paths.json` target, create or provide the required local data; several legacy/test evidence entries are intentionally not generated by a fresh installer.

Run `scripts/attentionbench/build_planner_chain.py --workspace DIR --dry-run` to inspect only the planner steps. `--report-official-diff` builds the environment, prints every source or prefix file whose bytes differ from the committed manifests, and reports whether each actual file contains the workspace path. It also reports dependency and distribution differences. This read-only report is for proposing a path exception list to the user; it never edits `allowed-path-files.json`. The official-content check still stops the chain before trust registration on any unapproved difference. The author's editable cuRobo installation is confirmed by its `direct_url.json`; its exact build isolation flags and any kernel compilation flags are absent from the available lock and runbook. The separate native ManiSkill scene path requires an 8.48 GB `scene_datasets` tree and its own lock.

The build proof runs as a standalone script under the newly built cuRobo Python with `-B -I`. It imports official cuRobo from `repos/curobo` and the d06 planner adapter from the d06 project, executes the committed two-plan request set, and records request and result hashes. It does not use `V2Service` or call `identity.load_lock`; it is **evidence that the locally built chain plans, not a trust decision**. Registry creation follows the proof and remains subject to the approved official-content rules.

The parent project inventory is not part of the official content comparison. The original r12 native task tree's `.git/config` identifies `https://github.com/TidyBot-Services/maniskill-robocasa-tasks.git`, its HEAD is `b18bbf1`, and all 122 runtime source files in the inventory match that public commit byte for byte in the available local checkout. A local assembly comparison against r12 found zero differences in the 179 `config/openarm-model` files, 22 `config/openarm_description` files, 122 native task source files, and 24 Franka meshes. The model inputs come from tracked `openarm_phase0_recheck/model/compat_v6`; the robot YAML is stored as a root-substituted template. Most Franka meshes come from the pinned official cuRobo source. Three project-specific meshes are now carried in this checkout. Every excluded author-only or generated inventory entry and its reason is listed in `scripts/attentionbench/r12-project-omissions.json`: 256 Git administrative files, five generated egg-info files, four acceptance-run files, and the optional CUPTI probe source and compiled library. The 1,237 copied project files form the parent snapshot; d05 still checks its full locked inventory before deriving.

**Remaining portability gate:** `r12-prefix-files.json` requires exact hashes for the editable cuRobo finder and `direct_url.json`, which contain the author's absolute source path. A fresh path may differ; `--report-official-diff` identifies the exact bytes and path-bearing files for review. Do not treat offline unit tests or `--skip-planner` as planner attestation.
