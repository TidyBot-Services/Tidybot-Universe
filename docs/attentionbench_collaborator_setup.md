# AttentionBench collaborator workspace

## Prerequisites

Use Linux x86_64 with an NVIDIA GPU and a working driver, Git, Python 3, `uv`, Conda, `bwrap`, enabled unprivileged user namespaces, and a Codex account with access to `gpt-6.1-sol`. Reserve roughly 50 GB for installed software and assets and **at least 60 GB free** before bootstrap. `doctor` enforces the latter. Sign in with `codex login`; install the CLI version pinned by `attentionbench.lock.json`.

## Four commands

From this repository:

```bash
scripts/attentionbench/bootstrap.sh --workspace /absolute/attentionbench-workspace --skip-planner
scripts/attentionbench/doctor.sh --workspace /absolute/attentionbench-workspace
scripts/attentionbench/start.sh --workspace /absolute/attentionbench-workspace
scripts/attentionbench/stop.sh --workspace /absolute/attentionbench-workspace
```

Use `bootstrap.sh --dry-run --workspace DIR` to print the whole plan without creating `DIR`. To use a complete existing official RoboCasa asset tree, add `--assets-from /absolute/path/to/robocasa/models/assets`; it is only read and SHA256 checked. Rerun with `--update` after changing lock inputs. Without `--skip-planner`, bootstrap reaches the planner trust gate and reports the P5 requirement.

Bootstrap creates `repos/`, `envs/`, `sim/`, `deployments/`, and `data/`; checks out exact commits; makes a Python 3.10 UI environment, a Python 3.11 simulator environment, and a Conda cuRobo environment; downloads the official locked asset archives when needed and checks every installed file; writes relative `paths.json` values; initializes the UI and Memory stores; and creates private random Memory keys. The asset transfer and verification can take tens of minutes to hours depending on network and disk; the Conda/CUDA install can also take tens of minutes. Stamps make reruns skip completed steps with unchanged inputs. A changed step requires `--update`.

`start.sh` launches Memory on loopback port 8878 and the UI on loopback port 8769, waits for both health checks, and prints the UI address. PID files and logs are under `data/run/`. Use `--ui-port` and `--memory-port` to choose other ports. `stop.sh` terminates only processes recorded in that workspace.

## Troubleshooting and current limit

Each bootstrap error names its step, command failure or mismatch, and a repair. If asset verification fails, the listed files must be replaced from the official source; bootstrap never changes mismatching files. If `doctor` reports no GPU, check the NVIDIA driver and `torch.cuda.is_available()` in `envs/curobo/bin/python`. For isolation failures, install bubblewrap and enable unprivileged user namespaces. For login or version failures, run `codex login` or install the lock's CLI version. For a busy port, stop the owning process or choose another port at start. For a missing `paths.json` target, create or provide the required local data; several legacy/test evidence entries are intentionally not generated by a fresh installer.

Planner trust registration needs P5 (`identity.py` local dev trust), not implemented yet. The author's d05/d06 builders contain absolute author paths and parent lock hashes, so a new machine cannot safely register an equivalent planner chain with the current identity policy. `--skip-planner` prepares the remaining workspace; it does not attest planner readiness. The separate native ManiSkill scene path requires an 8.48 GB `scene_datasets` tree and its own lock. The cuRobo planner service uses project robot/config assets and does not import that scene dataset.
