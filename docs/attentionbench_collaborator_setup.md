# AttentionBench collaborator workspace

## Prerequisites

Use Linux x86_64 with an NVIDIA GPU and a working driver, Git, Python 3, `uv`, Conda, `bwrap`, enabled unprivileged user namespaces, and a Codex account with access to `gpt-6.1-sol`. Reserve roughly 50 GB for installed software and assets and **at least 60 GB free** before bootstrap. `doctor` enforces the latter. Sign in with `codex login`; install the CLI version pinned by `attentionbench.lock.json`.

## Four commands

From this repository:

```bash
scripts/attentionbench/bootstrap.sh --workspace /absolute/attentionbench-workspace --planner-project-from /absolute/r12-project-bundle --planner-native-assets-from /absolute/native-assets
scripts/attentionbench/doctor.sh --workspace /absolute/attentionbench-workspace
scripts/attentionbench/start.sh --workspace /absolute/attentionbench-workspace
scripts/attentionbench/stop.sh --workspace /absolute/attentionbench-workspace
```

Use `bootstrap.sh --dry-run --workspace DIR` to print the plan without creating `DIR`. To use a complete existing official RoboCasa asset tree, add `--assets-from /absolute/path/to/robocasa/models/assets`; it is read and SHA256 checked. `--skip-planner` prepares the rest of the workspace. The planner chain needs a complete r12 project tree (`--planner-project-from`) and the 70,254-file native asset tree (`--planner-native-assets-from`); the builder checks both against committed inventories. The project source defaults to this checkout and native assets default to `DIR/data/robocasa365/assets` when the options are omitted. Missing or differing inputs stop the chain with the affected step and entries.

Bootstrap creates `repos/`, `envs/`, `sim/`, `deployments/`, and `data/`; checks out exact commits; makes a Python 3.10 UI environment, a Python 3.11 simulator environment, and `envs/curobo-env` from the committed Conda and pip specifications; downloads and verifies the official locked assets; writes relative `paths.json` values; initializes the UI and Memory stores; and creates private random Memory keys. The planner step checks the official source and 70,254 native files, writes an r12-schema official lock, derives d05 and d06, runs two fixed owned dev-tier plans, writes a protected 0444 local trust registry, and materializes a dev-local snapshot. Planner stamps are under `data/installer/stamps/`. The native tree is about 8.2 GB, the author's cuRobo environment about 15 GB, and the r12 project about 70 MB. Allow at least 60 GB free; asset transfer, hashing and Conda installation can each take tens of minutes or longer. A changed planner stamp requires repair of its inputs or removal of that step's outputs and stamp before retrying.

`start.sh` launches Memory on loopback port 8878 and the UI on loopback port 8769, waits for both health checks, and prints the UI address. PID files and logs are under `data/run/`. Use `--ui-port` and `--memory-port` to choose other ports. `stop.sh` terminates only processes recorded in that workspace.

## Troubleshooting

Each bootstrap error names its step, command failure or mismatch, and a repair. If asset verification fails, the listed files must be replaced from the official source; bootstrap never changes mismatching files. If `doctor` reports no GPU, check the NVIDIA driver and `torch.cuda.is_available()` in `envs/curobo/bin/python`. For isolation failures, install bubblewrap and enable unprivileged user namespaces. For login or version failures, run `codex login` or install the lock's CLI version. For a busy port, stop the owning process or choose another port at start. For a missing `paths.json` target, create or provide the required local data; several legacy/test evidence entries are intentionally not generated by a fresh installer.

Run `scripts/attentionbench/build_planner_chain.py --workspace DIR --dry-run` to inspect only the planner steps. The chain builder also accepts `--project-from` and `--native-assets-from`. The official-content check reports source, distribution, dependency, prefix file and native asset differences and stops before trust registration. The author's editable cuRobo installation is confirmed by its `direct_url.json`; its exact build isolation flags and any kernel compilation flags are absent from the available lock and runbook. If that difference changes installed metadata, the prefix manifest check stops rather than silently trusting it. The separate native ManiSkill scene path requires an 8.48 GB `scene_datasets` tree and its own lock.

**Current portability blockers:** The committed `r12-prefix-files.json` requires exact hashes for the editable cuRobo finder and `direct_url.json`; both contain the author's absolute source directory. A correctly installed editable package under a different workspace path changes those hashes, and `allowed-path-files.json` has no exceptions. The builder therefore stops at the official-content check on a fresh path. Separately, `V2Service` requires an already approved d06 lock, while local registry creation requires a passed build proof; the requested proof-before-registration order has no approval path. The builder leaves these gates intact. The committed r12 project inventory also includes 615 files absent from this checkout, so a complete project source bundle is needed. Do not treat the offline unit tests or `--skip-planner` as planner attestation.
